# 问卷星批量作答控制台

作者：Richard Huang · 本项目完全免费，禁止商用与学术造假

浏览器界面的逐题作答工具。HTTP 与 Playwright 双引擎，支持按轮次配置选项概率、联动选项补充填写、填空候选池。

[下载最新版本](https://github.com/gdfshzh/wjx-autofill/releases/latest) · [功能详解](docs/FEATURES.md) · [接口](docs/API.md) · [构建](docs/BUILD.md)

## 快速开始

### 方式一：Windows 免安装（推荐）

不需要装 Python，Win10 / Win11 x64 直接跑。

| 产物 | 体积 | 启动方式 |
|---|---|---|
| `wjx_probe_win64.exe` | 69.9 MB | 双击。首次约 15 秒解压运行时，之后约 4 秒 |
| `wjx_probe_portable_win64.zip` | 59.5 MB | 解压后双击 `启动.bat`，秒开 |

两个都自带 Python 3.13.12 与全部依赖，不写注册表、不碰 PATH。启动后浏览器自动打开 `http://127.0.0.1:8765`。

目标机器需要装有 Edge 或 Chrome（Win10/11 默认带 Edge），浏览器引擎用系统浏览器，不额外下载 Chromium。

### 方式二：源码运行

```bash
git clone https://github.com/gdfshzh/wjx-autofill.git
cd wjx-autofill
python -m pip install beautifulsoup4 lxml playwright curl_cffi
python server.py
```

启动参数：

```bash
python server.py --port 9000      # 换端口，默认 8765
python server.py --no-browser     # 不自动开浏览器
```

## 使用流程

1. 顶栏填问卷短链（如 `OfJ8WKu`）或上传二维码 → 点「抓取并解析」
2. 答题区勾选答案。可以只勾一部分，剩下由后端随机补齐
3. 设置「次数」与「间隔」
4. 点「开始作答」

运行期间的填题过程、当前题号、进度、日志都在同一屏内联动。运行结束会把第 1 轮实际提交的答案回填到答题区。

## 界面

```
┌─ 顶栏 ── 品牌 · [📷 二维码] [短链] [抓取并解析] · 问卷标题 ─┐
├─ 答题区 ─────────────────────────────────────────────────┤
│  答题区  18/18   [模板配置] [选项概率] [复制题目] [随机] ...  │
│  ● 逐题填写中  1/3  Q11 · …  [每轮随机] 次数 间隔 [开始][停止] │
│  ─────────────── 进度条 ─────────────────────────────────  │
│  Q1 …  Q2 …  Q3 …（题目卡片，独立滚动）                    │
├─ 日志 ────────────────────────────────────────────────────┤
│  22:20:34  第 1/1 轮 成功  joinid=128153311680              │
└──────────────────────────────────────────────────────────┘
```

状态灯只有一颗，由两路数据合成：灰=未开始，蓝（呼吸）=进行中，黄=验证码拦截，绿=本轮完成，红=失败。

控制坞那一行从左到右是：状态灯、阶段、`12/400` 轮次、总体百分比、当前题、剩余时长。
进度条按「已完成轮数 + 当前轮内进度」推进，不是单轮内那 17 题；剩余时长用已花时间
除以完成比例反推，刚开跑时进度不足 0.5% 先不显示，避免数字乱跳。

支持的题型：单选、多选、矩阵量表、填空（单行/多行）、下拉、量表、排序、矩阵填空、联动选项。

## 三种随机机制

这三个机制互不干扰，可以只开其中一个。

| 机制 | 入口 | 管什么 | 优先级 |
|---|---|---|---|
| **概率配置** | 工具条「选项概率」 | 指定的题按设定比例精确分配次数 | 最高 |
| **每轮随机** | 控制坞开关 | 未配置概率的选择题每轮重抽 | 中 |
| **填空模板** | 工具条「模板配置」 | 填空题按候选池逐轮取值 | 独立 |

优先级顺序：某题配了概率就按配额走，即使「每轮随机」是关的。没配概率的题仍按开关走。填空题不参与选择题随机，只走候选池。

### 选择题概率

每道题一份配置，对整批生效，不需要逐轮设置。填的是每个选项的出现比例，
代码按控制坞的「次数」换算成**精确次数**：

```text
400 轮、A 设 70% → A 出现 280 次，一次不差
1000 轮、70/20/10 → 700 / 200 / 100
```

| mode | 适用 | weights 含义 |
|---|---|---|
| `single` | 单选 / 下拉 | 相对权重，保存时归一化 |
| `multi_target` | 多选 | 每个选项的目标出现概率 |
| `multi_weight` | 多选 | 相对权重，按平均项数换算 |
| `matrix` | 矩阵量表 | 分值 1..N 的分布，每行独立 |

改完数字实时换算，右侧每行直接显示 `×次数`；底部给出平均项数和与目标的最大偏差。

### 联动选项

有些题的选项带补充输入框（如「其他，请注明」），选中后才显示且可能必填。解析时会记录 `has_text` / `text_required`，提交串按 `选项值^补充文本` 编码。

补充文本的取值顺序：模板候选 → 界面手填 → 选项名兜底。每个选项各自配候选，不会把 A 选项的说明贴到 D 选项上。

### 填空模板

每行一个候选，可开关「每轮随机取值」。开启时按洗牌队列取，候选够多时前 N 轮不重样；关闭时固定取第一项。

模板按问卷指纹绑定，换问卷后旧模板标 stale，不会误套。

## 命令行

图形界面之外还有一套完整 CLI：

```bash
python run.py doctor                  # 环境自检
python run.py qr --image qr.jpg       # 二维码解码
python run.py parse --url <链接>       # 抓页面解析出 survey.json
python run.py fill --url <链接>        # 真浏览器逐题填写
python run.py batch --url <链接> --count 5 --gap 60   # HTTP 批量
python run.py pipeline --qr qr.jpg    # 二维码 → 解析 → 提交 一条龙
python run.py gui                     # 网页控制台
python run.py probe --levels 1,2,4,6  # 探测本机并行上限
python run.py par --job "OOHKkG8:3" --workers 3   # 并行作答
```

## 参数

| 参数 | 默认 | 范围 | 含义 |
|---|---|---|---|
| 次数 | 3 | 1–5000 | 开几轮。每轮新建独立浏览器上下文，相当于一份全新答卷；概率配额按这个数换算 |
| 间隔 | 60 | 0–7200 秒 | 上一轮结果返回后倒计时，结束后才开下一轮 |
| 代理 | 空 | — | 窄屏隐藏，宽屏可填 `http://host:port` |

「无头运行」开关已移除：无头模式验证码几乎必弹且无法人工接管。需要无头时走命令行 `python wjx_browser.py --headless`。

## 验证码

触发后控制坞变暖色、进度条变黄，提示条出现。

脚本会先自动点三轮（贝塞尔轨迹、随机落点）。点不过就转成「等待你点验证」，你在弹出的浏览器窗口点一下即可，脚本检测到通过后自动继续，最多等 5 分钟。

## 自动更新

每次启动 3 秒后查一次 GitHub 上的最新 Release，版本号比当前大就弹窗：

```text
发现新版本 v1.5.0
当前 v1.4.1 · 最新 v1.5.0
[更新说明正文]
[稍后提醒]  [更新]
```

- **更新**：下载新版 exe 到同目录 `.new`，生成替换批处理，本进程退出后由批处理
  覆盖并重启。问卷数据与配置保留（`survey.json`、`choice_weights.json`、
  `fill_template.json` 不在覆盖范围内）。
- **稍后提醒**：记进 `localStorage`，同一版本不再打扰，下个版本出现时再提示。

只对 exe / 便携版生效。源码运行时点「更新」会提示改用 `git pull`，
因为当前进程占着文件，无法自我替换。

查询失败（离线、限流、超时）只记一条日志，不影响启动和使用。
接口见 [docs/API.md](docs/API.md)，结果缓存 10 分钟。

## 接口

本地 HTTP 服务，前端与后端之间走 JSON。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/survey` | 当前问卷结构、短链、指纹 |
| POST | `/api/survey` | 抓取并解析，落盘 `survey.json` |
| POST | `/api/quick/start` | 开始作答 |
| POST | `/api/quick/stop` | 停止（会终止浏览器子进程） |
| GET | `/api/quick/status` | 运行状态与结果 |
| GET | `/api/browser/status` | 浏览器阶段、当前题、轮次 |
| GET | `/api/weights` | 概率配置 |
| POST | `/api/weights` | 保存 / 清除 / 复制配置 |
| POST | `/api/weights/preview` | 按配置跑蒙特卡洛预览 |
| GET/POST | `/api/fill/template` | 填空与联动模板 |
| GET | `/api/survey/export` | 题目文本 |
| GET | `/api/update/check` | 查最新 Release，比对版本 |
| POST | `/api/update/apply` | 下载并安排重启替换 |

完整请求体、返回结构、示例见 [docs/API.md](docs/API.md)。

## 常见问题

**双击 `启动.bat` 报「错误码 9009」**

PATH 里没有可用的 Python，或命中的是 Microsoft Store 那个 0 字节的 `python.exe`。脚本会按四个候选路径实测查找；全都没有就改用免安装版 exe。

**别的电脑上日志乱码**

子进程用系统 locale 输出、父进程按 UTF-8 读，中文会碎。已在 `console.py` 里统一 `reconfigure(encoding="utf-8")` 并设 `PYTHONIOENCODING`。旧版本遇到这个问题就升级。

**点「停止」没反应**

停止会直接 `terminate` 浏览器子进程，2 秒内生效。如果异常发生在浏览器启动之前，状态位会卡在 running，1.3.0 之后已加 `finally` 复位与接口兜底。

**某道题填不进去会怎样**

脚本会立即停手，不再作答后续题目，也不提交，同时弹窗告诉你是哪道题、哪一行、什么原因
（例如「Q21 · 第 7/16 行 · 矩阵量表：第 7 行点击后未选中（目标 5，实际 无），
行标题：可以传承与发扬红色文化」）。整批任务一并中断，后续轮次全部取消。

**怎么判断提交成功**

只看是否跳转到含 `joinid=` 或 `joinactivity=` 数字的页面，不看正文里的「感谢」二字——那个词在 `<meta og:description>` 里也有，会误判。

**换问卷后模板/概率失效**

配置按问卷指纹（题干+题型+选项的 MD5）绑定。换问卷后旧配置标 stale，不会套用到新问卷上。

其他排障记录见 [docs/INTERNALS.md](docs/INTERNALS.md)。

## 运行环境

- Python 3.8+，服务端只用标准库
- `beautifulsoup4` + `lxml`：解析问卷页面
- `playwright`：浏览器作答，用系统 Edge / Chrome
- `curl_cffi`：HTTP 模式的 TLS 指纹
- `zxing-cpp` + `pillow`：二维码解码（可选）
- `psutil`：并行探测（可选）

```bash
python -m pip install beautifulsoup4 lxml playwright curl_cffi
```
